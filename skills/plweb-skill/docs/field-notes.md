# 实测补充（以现场行为为准）

本页记录真实账号长期运行中发现的行为：接口文档没有写全、或者旧笔记已经过时的部分。每条都注明实测日期；与其它文档冲突时按**较晚的实测**判断，但仍以接口实际返回为准。

## 1. 列表分页：`Take` 大于 16 会让服务端挂起

- 实测 `Take > 16` 时请求**不返回、不报错**，一直拖到客户端超时，看起来像网络故障或账号异常。
- 处理：单页固定 `Take=16`（或更小），用 `Skip` 累加实际返回条数翻页；不要为了"一次拿全"把 `Take` 调大。
- 作品列表用 `From=末条摘要ID, Skip=0`；评论用 `CommentID=末条评论ID, Skip=0`，按 ID 去重。
- 随附 `fetch_works`、`fetch_comments` 已内置该上限；自行用 curl/Python 发请求时要自己守住。

## 2. 写操作偶发 `403 User.Not.Allowed` 多是临时限流，不是封号

- 实测连续快速发帖会被**临时限流**，几小时后自动恢复；同账号次日的评论、点赞恢复 200。
- 处理：当次停手、下个唤醒/下一轮再试，别把一次 403 说成账号被封。
- 不换账号、不换 IP、不拆批来绕限流；那是规避行为，不是修复。
- 真正的权限拒绝（改别人作品、给自己加精选、无编辑权限）不会自愈——用只读接口核对权限与标签后如实报告。

## 3. 社区没有普通用户私信接口

- `Messages/SendMessage` 实测 **405**（路由不存在）；`Messages/SendMessages` 是管理员模板消息专用。
- 半私密交流走**对方留言板**：`Messages/PostComment`，`TargetType="User"`，`TargetID` 用对方用户 ID。
- 返回 405/404 就是"这个路径不存在"的信号，不要顺着猜 `/Messages/SendPrivate`、`/Contents/Star` 之类的变体。

## 4. 系统通知接口会偶发挂起

- `Notifications/Get` 即使参数正确也会偶尔不返回。单次快速尝试，失败就放弃，不要循环重试。
- 站内信 `Messages/GetMessages` 已覆盖主要通知内容，优先用它。

## 5. 收件箱（`Messages/GetMessages`）的正确读法

- 消息数组在 `Data.Messages`；`Data.$values` 是旧版本误用，读到永远是空。
- `Unread` 是状态标记不是数量：`0` 为未读，非零是读取时间戳。
- `Skip=0` 的第一页会**清零聚合未读计数**，是有状态读取；需要保留"有未读"这个事实时先读再处理，别反复刷第一页。
- 排序不是时间倒序，自己按 `Timestamp` 排。
- 回复要触发对方通知，正文必须带内联标记 `回复<user=对方ID>@对方昵称: 正文`；纯文本正文**不会**通知对方。

## 6. 签到与活动奖励

- `POST /Users/SyncActivities`，body `{}`：返回 `Data.Activities`（`InterfaceModel == "Attendance"` 为每日签到，`"Upgrade"` 为升级奖励）与 `Data.Statistic`；`Activities[].Avails` 是当前可领档位。
- `POST /Users/ReceiveBonus`，body `{"ActivityID", "Index", "Statistic"}`：三个字段都必填，`Statistic` 原样回传。
- 当天已领返回 `403 Activity.Bonus.Received`，这是正常状态，不是错误；首次注册当天服务端自动首签。
- 签到幂等、不耗预算，每天第一次运行调用一次即可。

## 7. TLS：早期需要关闭校验，现已恢复正常

- 2026-09 的笔记记录该域名与证书不匹配，运行环境需关闭证书校验。
- 2026-11-16 复测：`physics-api-cn.turtlesim.com` 与 `physics-api-us.turtlesim.com` 证书链校验**通过**（TLSv1.3）。
- 结论：不要再全局 `verify=False`。只有遇到真实证书错误时局部豁免，并在笔记里记下日期和错误原因。

## 8. 讨论帖的 Workspace 不能为空

- 完全空的场景（0 元件）提交会 `403`。讨论帖也要至少一个元件，用"电池+开关+灯"这类最小场景即可。

## 9. 复测约定

- 每条实测写清日期；超过两周的结论在使用前复核一次。
- 客户端挂起/超时，先怀疑 `Take` 过大和临时限流，再怀疑网络。
- 写操作超时先核对已有结果，避免重复发布、重复领取或重复扣币。
